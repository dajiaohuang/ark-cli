## 实际费用入口与本人范围

以下是独立回归的验收契约，不把基线历史金额或固定日期注入原题。原题按原实验集 query 原样提交；日期、资源与费用从该次真实工具证据核对。静态文字检查和命令成功不能代替 Agent 实际执行路径。

| 场景 | 输入 / 证据 | 验收 |
| --- | --- | --- |
| 本人已发生用量折算费用（163678） | 使用原题；冻结 4363 的失败证据：先 usage/pricing、两种本人筛选失败后去掉 mine、最终给单价估算 | 金额意图先读取 Billing 并查询实际应付；按本轮当前自然周及 T+1 说明范围；不以账号混合 Token 乘目录价冒充个人实际花费。费用/范围无法查询时明确未知，不编造历史 GT 数值 |
| 目录询价控制 | “某模型每百万 Token 多少钱”且未问已发生消费 | 走 Pricing 的真实目录价及计量单位；不误进个人账单，不发推理请求 |
| 用户明确要求估算 | 用户指定模型、输入/输出数量与范围，要求按单价预测成本 | 可组合 Usage/Pricing 或使用用户给出的数量；读取实际字段并数值计算，标估算，披露免费额度、缓存、折扣与结算差异；不把估算称为实际应付 |
| 纯数量控制 | “本周我用了多少 Token/请求” | 使用正确的 Usage 数量入口；金额路由不抢占数量查询，不为统计生成新调用 |
| 无本人 Endpoint | CLI 非零退出且明确 `no endpoints found ... omit --mine` | 只可尝试本人 apikey 维度一次，其余条件保持；不把 CLI 提示当扩大范围的确认 |
| Key selector 为空但 SID 存在 | 已知非空 fixture：本人 Active 项有 SID，但 Key 掩码后缀为空；另一个 Active 项后缀非空作为对照 | 区分 Usage 后缀筛选与 Billing SID 筛选；不能从 Usage 错误推出账号无 Key、无调用或费用为零，不导出明文/新建 Key 来修统计 |
| 无交互回复的本人范围 | endpoint 与 apikey 均未取到结果；用户没有明确批准账号范围 | 交付已查范围、实际错误及未知项；不会自行删除 mine，不以“我会查全量”的通知代替用户确认 |
| 用户另行指定账号全量 | 先前个人查询缺口后，用户明确要求全账号 | 才扩大范围并标注可能包含其他用户；保留原日期、模型等条件，不再称个人用量 |
| 空、真实零与错误 | 成功空 records；非空记录且指标为0；非零退出/解析失败，各一项 | 三者分别呈现，不用同一个“无消费”结论；前两项对照验证读取器确实能区分非空和空 |

源码依据：`shortcuts/usage/stats.go` 的 `applyMine` / `listMyAPIKeySuffixes`、`shortcuts/billing/list.go` 的 `resolveMyAPIKeySIDs`。新候选须在真实挂载后验证路由及范围；本页的固定 fixture 仅用于解释和校准，不能充当云端查询结果。
