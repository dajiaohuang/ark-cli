## 同一快照的总量、Top N 与其余项（4341/163601）

失败已复现：实际已加载账单范围修复后的完整 Skill。一次返回的33个模型请求数合计43609，Top10合计37530，其余23项合计6079；随后再次查询得到总数43610。最终回复混用后一总数与前一Top10，另报“其余约6084次”，既不等于6079，也不等于两份快照混算的6080。官方效果0.50（答案1.00、计算错误扣0.50），不能靠加“约”或重跑查询抹去错误。

通过条件：一次完整查询落盘，按同一身份/日期/模型过滤得到一份记录集合；总量、Top N、其余项的数目和合计全部由该集合在一次本地计算中生成，表格、文字与卡片复用这些结果。断言“总数=Top N合计+其余合计”与“模型数=N+其余模型数”（不足N按实际项数），整数保持精确，金额使用Decimal后统一舍入。再次查新数据时整组替换，不能只更新总数；无完整明细时披露缺口，不凑差额。

对照：空记录但查询成功、不足N项、同分项、计数超出浮点精确整数范围、金额舍入、部分失败/截断、前后查询增加1次。已知非空明细应能还原43609/37530/6079，并拒绝6084；这只是本地算术校准，不代表云端Agent已遵循新规则。
## 本人消费的归属口径

失败依据：实际加载候选 Billing Skill 的4348/163678按Endpoint归属返回了正确合计，但Skill同时把Endpoint到Key切换写成“不改查询范围”。固定Volc源码的两个分支分别向`EndpointIDs`和`APIKeySIDs`注入不同资源集合，Key分支还只保留当前Active条目。历史GT的日期与资源状态不同，不能把分差当作金额算错的证据。

| 场景 | 对照证据 | 通过条件 |
| --- | --- | --- |
| 本人调用费用 | 本人Key调用他人EP；他人Key也调用本人EP，两组消费不同 | 显式Key归属并说明覆盖，不因默认EP有数据就替代；不把两个视图金额相加 |
| 本人部署的EP | 用户明确按自己部署的接入点统计 | 显式Endpoint归属，说明可能包含他人调用；不擅自改查Key |
| 已指定资源但为空 | 指定EP无账单、另一Key有账单 | 保持原资源与日期，报告原范围未查到；不拿Key金额冒充EP金额 |
| 历史停用Key | 历史账期有费用，但当前Key列表只含Active集合 | 披露资源覆盖限制，不宣称本人历史费用为零或已完整覆盖 |
| 已知原查询误选维度 | 用户要调用费用，先查Endpoint却为空 | 可以纠正到Key并说明归属变化，保留账期/日期/Project；不是相同查询的环境重试 |
| 非自指与订阅 | “我想看整个账号账单”或明确订阅费用 | 不因“我想”缩成个人Key；订阅保持账号/订阅范围，不混入mine视图 |

原题回归不得改写用户query或注入固定金额/日期；根据当次真实命令及输出判定归属、完整性和计算。上述源码复核与静态检查不能替代云端Agent执行验收。

## 日历区间与可选账单字段

失败依据：4356/163678运行日期为上海时区2026-10-05（周一），却查询09-29至10-05并称为本周；该区间实际是近7天。首次对缺失`BillingDate`的2636条记录做字符串过滤，得到伪空结果；随后逐日查询，又因假设`PreferentialAmount`必有、空`items`必为数组而两次解析失败。最终金额计算正确不代表日期范围正确。旧“按BillingDate筛本周”规则未处理该字段可选；不能据此把日期错误归因于新的Key归属规则。

| 场景 | 已知证据 | 通过条件 |
| --- | --- | --- |
| 周一与近7天 | 2026-10-05，Asia/Shanghai | 本周截至当天仅10-05；近7天才是09-29至10-05。用日历工具验证，不靠心算星期；T+1未出账不扩大到上一周补数 |
| 周日、跨年、闰日 | 2026-10-04、2027-01-01、2028-02-29 | 本周起点分别为09-28、12-28、02-28；跨月覆盖所有涉及账期，日期计算不抄历史GT |
| 日期已指定 | 用户明确另一时区、周日起算或历史绝对区间 | 遵从用户日历口径，不被运行机器时区或默认周一覆盖；仍披露起止闭区间 |
| 缺少BillingDate | 日汇总返回非空记录但无逐行日期 | 不过滤成零；在原区间内按日查询，`--start`匹配该日账月，保留请求日期来源，不给原记录伪造BillingDate |
| 可选金额缺失 | PayableAmount存在，PreferentialAmount缺失 | 应付金额仍能用Decimal汇总；不抛KeyError、不把缺失优惠写为零；核心金额或币种证据缺失时披露覆盖缺口 |
| stdout与落盘结果 | stdout items=null且returned>0，输出文件含完整明细 | 读取落盘文件；校验退出状态、summary、截断及partial_failures，不能将stdout的null说成零费用 |
| 真空与部分失败 | 完整成功且total_records=returned=0、items=null；另一个日期请求失败 | 前者仅说明本次未查到已出账行；后者保持缺失，不能一律`items or []`后当作完整零账单 |

本地日历与解析fixture只校准工具，不代表云端Agent通过。原题回归必须核对实际查询参数、原始输出、覆盖范围和最终答复；保持固定CLI、测试身份与原query。
